Why the VLM runs on the GPU on the AGX Orin, and on the NPU on the IQ9

Both boards run the vision-language model on their main AI engine. That engine is a different kind of hardware on each board.

The short answer

The AGX Orin has NPU-style accelerators (two NVIDIA DLAs), but they are built for convolutional vision networks such as YOLO and can't run a transformer like a VLM. NVIDIA put most of the Orin's AI compute into the GPU's Tensor Cores, so LLMs and VLMs run there. Qualcomm made the Hexagon NPU the IQ9's main AI engine and ships a compiler (QAIRT) that puts transformers on it, while its Adreno GPU is relatively weak for AI. So IQ9 NPU vs Orin GPU is a fair comparison: each board's best engine for the job.

Know before you present
  • Both boards run Qwen3-VL-4B-Instruct (4-bit). The Orin's live demo uses Ollama, which gives each frame ~4× more image detail than the IQ9 (~1,100 vs ~270 tokens): about 3.7 s per answer live, vs 2.3 s when the detail is matched.
  • In the traffic demo the Orin's default detector is YOLOv8n (the IQ9 uses YOLO26n). On the highway video both find the same vehicles; YOLOv8n is faster on the DLA. YOLO26n is one click away in the traffic settings.
  • Neither detector runs fully on the DLA: the final detection layers fall back to the GPU on both models (see below).

Why a VLM can't run on the Orin's DLA

The DLA is a fixed-function engine for convolutional networks. A VLM is a transformer and needs things the DLA doesn't support:

  • Attention layers and very large matrix multiplications.
  • A KV cache: the model's memory of the text so far, which grows with every word.
  • Changing input sizes: every prompt and answer has a different length; the DLA wants fixed shapes.
  • A limited layer set (convolution, pooling, activations) in INT8 or FP16, compiled ahead of time with TensorRT, and a maximum tensor dimension of 8192.

That's why every LLM/VLM runtime for Jetson (llama.cpp, Ollama, TensorRT-LLM, vLLM) uses the GPU. NVIDIA describes the DLA as a throughput and power-efficiency engine, not a lower-latency one; layers it can't run fall back to the GPU, and every switch costs time.

Qualcomm designed the Hexagon NPU as a general AI engine and ships QAIRT, which compiles transformer models for it. On the IQ9 the NPU processes the image and prompt about 20× faster than its CPU or GPU, which is where nearly all of its advantage comes from.

Likely questions

Does the Orin have an NPU?

It has two DLAs (Deep Learning Accelerators), NVIDIA's NPU-style engines, plus a PVA for classic vision. They run CNNs like YOLO, not transformers. The traffic demo labels the DLA "NPU" so the two boards line up; the main AI engine on the Orin is the GPU.

Which board is faster?

With the same model and the same image detail, one answer takes about the same time: 2.3 s on the Orin GPU vs 2.4 s on the IQ9 NPU. The IQ9's NPU gets the first word out sooner (0.63 s); the Orin's GPU writes the rest faster (~26 vs ~16 tokens/s). The Orin also has headroom for bigger models (8B-12B run on this board).

Do both boards run the same models?

The VLM is the same: Qwen3-VL-4B-Instruct on both, 4-bit (Qualcomm's W4A16 build on the IQ9, llama.cpp's Q4_K_M on the Orin). The detector differs: the Orin's traffic demo uses YOLOv8n by default because it suits the DLA better; YOLO26n, the IQ9's detector, gives the same detections on the highway video and can be selected live.

How much power does it use?

The Orin measures its own module power: about 17 W while answering a VLM request in MAXN mode (live in the Platform panel and the stats header). The module's power modes span 15-40 W. The IQ9 has no on-board power sensor, so its demo can't show a live figure.

Why not run the VLM on the DLA to save power?

The DLA can't run transformer layers (attention, KV cache, dynamic shapes); TensorRT would send nearly every layer back to the GPU. The DLA's job in a pipeline like the traffic demo is to take the detector off the GPU so the GPU stays free for the VLM.

Is anything sent to the cloud?

No. Camera frames, the model and the answers all stay on the board on both demos.

Could the Orin be faster still?

Likely, with NVIDIA's own stack: TensorRT-LLM or a TensorRT-built vision encoder, INT8/FP8 quantization, or the 64GB module (275 TOPS, 2048-core GPU). These demos use the generic llama.cpp/Ollama path. A newer TensorRT (10.7) would also allow INT8 for the YOLO26 detector.

Running the demo on this board

  • Start: desktop icon VLM Demo + Cascade (opens the main demo; the car button opens the traffic demo, the house button returns). Stop: icon VLM Demo (Stop).
  • Traffic demo: press Start Detection, then click a vehicle card to have it described. The detector (NPU / GPU / CPU, YOLOv8n or YOLO26n) is in the settings drawer.
  • Camera: USB webcam (Trust Full HD, /dev/video0) is the default source in the main demo.
  • The page runs on https://localhost:8090; accept the self-signed certificate warning once.

Useful commands in a terminal:

jtop                           # live CPU / GPU / DLA / power / temperatures
nvpmodel -q                    # power mode (should say MAXN)
ollama ps                      # which VLM is loaded (should be qwen3-vl:4b-instruct, 100% GPU)
free -h                        # RAM: the GPU shares it, so loaded models count here
tail -f ~/live-vlm-webui-cascade/run.log   # demo server log
pkill firefox                  # if Firefox says it's already running

System updates are frozen until after the event (snaps held; snapd 2.77 breaks snaps on this kernel). The Hermes agent is switched off.
